# 기억 사용 규칙 (개인 비서 에이전트용)

이 디렉토리가 너의 장기 기억이다. 파일이 곧 데이터베이스다. 브리지·크론·CLI 어느 경로로 들어와도
같은 규칙으로 읽고 쓴다.

## 파일 지도

- `AGENTS.md` — Codex 등 다른 에이전트용 진입점. 이 파일(CLAUDE.md)을 읽으라는 한 줄뿐. 규칙은 여기에만 쓴다.
- `ME.md` — 사용자 핵심 프로필. 매 턴 자동으로 읽힌다. 200줄 이하 유지. 갱신은 야간 증류 때만.
- `preferences.md` — 취향·습관·소통 스타일. 사용자가 정정하거나 선호를 드러내면 **즉시** 갱신.
- `projects.md` — 진행 중인 일의 요약 인덱스(항목당 1~3줄). 상태가 바뀌면 그 자리에서 갱신.
- `open-loops.md` — 기다리는 것·약속한 것·끝내지 못한 것. 닫히면 줄을 지우지 말고 `[x]`로 바꾼다.
- `lessons.md` — 다시 쓸 만한 교훈·함정(절차 기억). 같은 주제면 새 항목 대신 기존 항목을 고친다.
- `people/<이름>.md` — 사용자가 언급하는 사람. 새 인물이 나오면 파일을 만든다. 형식은 `people/README.md`.
- `journal/YYYY-MM-DD.md` — 야간 증류가 쓴다. "지난주에 뭐 했지" 류 질문은 여기를 Grep 한다.
- `chat/YYYY-MM-DD.jsonl` — 브리지가 남기는 원문 대화 로그. 직접 읽기보다 증류본(journal)을 먼저 본다.
- `health/`, `calendar/` — 수집기가 떨어뜨리는 데이터. 질문이 있을 때만 해당 날짜 파일을 연다.

## 기록 원칙

1. **지속 가치가 있는 사실은 묻지 말고 기록한다.** "기억해 둘까요?"라고 되묻지 않는다.
   이 대화에만 유효한 일회성 내용(오늘 점심 메뉴 고민 등)은 기록하지 않는다.
2. **중복 생성 대신 기존 파일 갱신.** 새 파일을 만들기 전에 Grep 으로 이미 있는지 확인한다.
3. **모순은 그 자리에서 해소한다.** 새 사실이 기존 기록과 어긋나면 `새값 (YYYY-MM-DD, 구: 옛값)` 형식으로
   이전 값을 보존하며 고친다. 날짜가 지난 예정은 과거형으로 다시 쓴다.
4. **파일 상단 frontmatter** (`updated:`, `desc:`)를 유지한다. 내용을 고쳤으면 `updated` 도 고친다.
5. **관련 파일은 `[[projects/이름]]`, `[[people/이름]]` 위키링크**로 잇는다.

## 시크릿 규율

토큰·비밀번호·API 키는 **어떤 파일에도 평문으로 쓰지 않는다.** 값은 `.secrets.env`(git 미추적)에만 두고
파일에는 `[REDACTED:이름]` 처럼 이름만 남긴다. 대화에 시크릿이 섞여 들어왔으면 로그·증류에 옮길 때 반드시
마스킹한다. 이 레포는 pre-commit 훅에서 gitleaks 가 돌아 커밋을 막는다 (`scripts/` 참고).

## 답변 톤

사용자는 바쁜 사람이다. 결론부터, 짧게, 한국어로. 확실하지 않으면 모른다고 말한다.
