# 구조와 데이터 흐름

## 한 장 그림

```mermaid
flowchart LR
  subgraph phone[폰·외부 서비스]
    S[Slack DM]
    H[Health Auto Export]
    G[Google Calendar]
  end

  subgraph mac[항상 켜둔 맥]
    B[bridge/index.js<br/>Socket Mode · 동시성 1 · 세션 유지]
    C1[collectors/health-export-server.js]
    C2[collectors/gcal-ics-dump.py<br/>크론 30분]
    W[workers/delegate.sh<br/>git worktree + nohup claude -p]
    N[scripts/nightly-distill.sh<br/>크론 23:30]
    CL[(claude -p<br/>cwd = 기억 레포)]
  end

  subgraph mem[기억 레포 (git)]
    M1[CLAUDE.md · ME.md<br/>preferences · projects<br/>open-loops · people/]
    M2[chat/YYYY-MM-DD.jsonl<br/>원문 로그 · git 제외]
    M3[health/ · calendar/<br/>수집기 산출물 · git 제외]
    M4[journal/YYYY-MM-DD.md<br/>증류본]
  end

  S -- 메시지 --> B
  B -- 프롬프트 (stdin) --> CL
  CL -- 읽기/쓰기 --> M1
  CL -- 답 (JSON) --> B
  B -- 답장 --> S
  B -- append --> M2
  H -- POST JSON --> C1 --> M3
  G -- ICS --> C2 --> M3
  B -. 1분 넘는 일 .-> W
  W -- 완료 DM --> S
  N -- 읽기 --> M2
  N -- 읽기 --> M3
  N -- claude -p --> M4
  N -- 갱신 --> M1
```

네 층으로 읽으면 된다.

1. **기억 레포** — 마크다운 파일이 데이터베이스. 비서가 읽고 쓰는 유일한 상태. git 으로 백업·이력.
2. **브리지** — 입력 채널(슬랙)과 `claude -p` 사이의 얇은 관. 세션·타임아웃·직렬화만 책임진다.
3. **워커** — 오래 걸리는 일을 격리된 워크트리에서 돌리는 별도 claude 프로세스. 결과는 git 에, 알림은 DM 에.
4. **수집기** — 외부 데이터를 날짜별 파일로 떨어뜨리는 작은 스크립트. LLM 호출 없음.

가운데 `claude -p` 는 **상태가 없다.** 매 턴 기억 레포의 `CLAUDE.md` 를 읽고 시작하므로, 비서의 성격·규칙은 코드가 아니라
그 파일을 고쳐서 바꾼다. 코드는 거의 안 바뀌고 기억 레포만 자란다.

## 실제로 운영하며 배운 것 (일반화한 것만)

1. **파일이 DB 다. 검색은 Grep 이 먼저.** 벡터 검색·임베딩은 1년 넘게 필요 없었다. 파일 지도(`CLAUDE.md`)가 좋으면 비서가 어디를 열지 안다.
   의미 검색은 파일이 수백 개를 넘고 Grep 이 빈손일 때 보조로 붙이면 충분하다.

2. **"기억해 둘까요?" 를 금지하면 기억 품질이 올라간다.** 묻는 순간 사용자는 귀찮아서 "아니" 라고 하고, 그 사실은 사라진다.
   지속 가치가 있으면 기록하고, 틀렸으면 나중에 고치는 쪽이 낫다.

3. **시크릿은 한 번 새면 끝이다.** 대화에 붙여넣은 토큰이 증류본에 그대로 박혀 git 에 올라간 사고가 있었다.
   이후 규칙: 값은 `.secrets.env` 에만, 파일에는 `[REDACTED:이름]`, pre-commit 에 gitleaks. 기억 레포는 비공개여도 이 규칙을 지킨다.

4. **`--resume` 은 시스템 프롬프트 변경을 못 본다.** 세션을 이어가면 `CLAUDE.md` 를 고쳐도 다음 새 세션까지 반영이 안 된다.
   그래서 세션은 몇 시간 쉬면 끊고, 규칙을 바꾼 날은 `/new` 로 리셋한다. 세션은 "대화 맥락" 용이지 "기억" 용이 아니다 — 기억은 파일.

5. **동시성은 1 이 정답이었다.** 두 세션이 같은 `open-loops.md` 를 동시에 고치면 한쪽이 사라진다. 빠른 응답보다 기억이 안 깨지는 게 중요하다.
   병렬이 필요한 일은 워커로 빼서 다른 디렉토리(워크트리)에서 돌린다.

6. **브리지 턴은 짧게, 긴 일은 위임.** 턴 하나가 5분을 넘기면 그 사이 메시지가 전부 막히고 사용자는 "죽었나?" 한다.
   타임아웃 5분 + "1분 넘을 일은 워커에게" 규칙을 `CLAUDE.md` 에 적어두면 비서가 스스로 위임한다.

7. **야간 증류가 기억의 질을 결정한다.** 원문 로그는 쌓아두되 비서는 증류본(journal)을 읽는다. 증류 프롬프트에
   "어느 파일에 반영했는지 적어라" 를 넣으면 기억 파일 갱신이 빠지지 않는다. 증류본은 사람이 가끔 읽고 고쳐도 된다.

8. **모순은 덮어쓰지 말고 `새값 (날짜, 구: 옛값)`.** 선호나 결정은 자주 바뀐다. 이전 값이 남아 있어야 "왜 바꿨더라" 에 답할 수 있고,
   증류가 오래된 값을 다시 살리는 사고도 줄어든다.

9. **워커는 묻는 순간 멈춘다.** 프롬프트 첫 줄에 "질문할 사람이 없다, 기본값으로 결정하라" 를 쓰고, 결과는 반드시 git 에 남기게 한다.
   완료 알림은 유실될 수 있으니 알림이 안 와도 브랜치를 보면 결과가 있다.

10. **항상 켜둔 맥은 "켜져 있음" 을 믿지 마라.** 재부팅 뒤 launchd 가 안 뜨거나, 화면 잠금 비밀번호 창이 자동화를 막거나,
    잠자기 설정이 되돌아간다. `pmset` 으로 잠자기 끄기, launchd `KeepAlive`, 그리고 하루 한 번 "살아있니?" 를 비서에게 보내는 크론이 있어야 한다.

11. **구독 한도는 주간으로 소진된다.** Claude Max 는 5시간 창과 주간 창이 따로 있다. 야간 증류·수집기·워커가 몰리면 정작 낮 대화가
    한도에 걸린다. 크론은 분산하고, 워커에는 `--max-turns`·`--max-budget-usd` 같은 상한을 건다.

12. **외부로 보이는 행동은 사람 확인 게이트.** 메일 발송·슬랙 게시·결제는 비서가 초안까지만 쓰고 사람이 보낸다.
    처음부터 `CLAUDE.md` 에 "외부 발송은 금지, 초안만" 을 적어두는 편이 나중에 권한을 조이는 것보다 쉽다.
